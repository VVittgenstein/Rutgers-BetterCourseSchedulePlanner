### A3. 最终产品合同

#### desired 是唯一真相

- `desired_watches` 是本地程序权威的用户意图；
- 多页面平权编辑同一份服务端状态；
- 不使用 leader、Web Locks 或 BroadcastChannel；
- 不向其他页面实时推送 desired 修改；其他页面刷新/重新加载后读取；
- 每个 section 在进程中至多有一份物理 watch；
- 现有 `/api/v1/watch` 继续承载告警，并可向所有当前页面扇出，因此多个页面可能同时响；
- 最后一个 watch 页面离开时拆物理 watch、保留 desired；页面回来后重新装配。

#### desired 使用本地 HTTP

必须实现：

```text
GET /api/v1/local/desired-watch
PUT /api/v1/local/desired-watch
```

- 不注册 desired WebSocket；
- WebSocket upgrade 到 desired HTTP 路径不得变成新的 WS route；
- 普通 GET 不能继续按旧测试返回 404；
- desired 类型、路由和存储只能存在于 local-only 闭包；公网 SOURCE/API/STORAGE/PACKAGE/Cargo closure 继续零表面。

#### CAS 不做目录准入

- 删除 `commit_desired_watch_mutation` 的 admission callback；
- 删除只为写入期目录准入存在的 `DesiredWatchAdmission`、`DesiredWatchRejection`、`Rejected`、`Unavailable` 等语义；
- 删除系统因装配失败自动撤销用户意图的 `retire_desired_watch` 路径及其专用 outcome，除非静态证明它承担了与最终裁定无关且仍必需的职责；若存在这种情况，停止回报，不自行保留旧语义；
- CAS 只检查 generation、mutation receipt/fingerprint、based-on revision、9 门 post-state 上限、authority 资源预算与计数器边界；
- STOP 包括 base-0 STOP 继续写 tombstone；
- Catalog、term、campus、Open Sections 都不在 CAS 写入时检查；
- 物理装配时才检查目标是否可装；
- 装配失败保留 desired，在读取投影中暴露原因，由用户决定是否 STOP；
- 不得因永久装配失败自动写 `desired=false`。

#### receipt 与 HTTP 状态

- committed、terminal stale revision、terminal limit exceeded 继续按既有 receipt 合同幂等；
- stale generation、mutation-id conflict、authority full 等是否入 receipt 继续遵守已经被测试冻结的 store 合同；
- HTTP 状态由被重放的原业务结果决定，而不是因为外层叫 `REPLAYED` 就一律返回 200；
- committed/replayed committed：200；
- stale generation、stale revision、mutation id conflict、limit exceeded：409，并返回客户端重读/纠正所需的当前 generation/revision/maximum；
- authority full、SQLite busy/unavailable、当前无法安全给出权威结果：503，保持可重试且不得写伪终局 receipt；
- malformed protocol/body：沿用本地 API 的严格 400；
- 使用现有本地 Host/Origin/session nonce 边界，不另造旁路。

### A4. GET 权威投影

GET 必须返回一个严格版本化、本地专有的权威读取模型，足以让前端：

- 对 desired 和 tombstone 获取当前 revision；
- 获取 authority generation；
- 获取 desired policy 与 materialization epoch；
- 判断当前物理监控是否对应同一 generation/revision/epoch/policy；
- 显示 pending disarm、blocked-on-slot、暂态 retry 或装配失败原因；
- 在读取失败时显示失败，不得使用旧绿态冒充当前状态。

建议返回 authority entries（含 tombstone）与进程内 materialization snapshot；`armed` 可由严格字段推导，
不另存一个可能撒谎的冗余布尔值。最终字段名可遵循仓库现有 camelCase/strict-key 约定，但必须在 Rust、TS、golden/codec 测试中冻结。

旧 reduced-scope 文档的 32 KiB bootstrap 预算不能未经证明套到最多 521 行的 authority GET。
对 GET 使用显式本地响应预算，并用最大合法状态序列化测试证明不超限；优先采用已有 256 KiB 逻辑状态上界，
若仓库现有 HTTP 基础设施要求不同上限，应给出定量证明并在回报中披露，不得静默截断、分页漏状态或移除 tombstone。

### A5. 本地 DesiredWatchCoordinator

实现一个 local-only、进程级的 coordinator/materializer。名称可按现有代码风格调整，但职责必须集中：

- 读取和提交 desired authority；
- 在阈值/资源压力下安全触发 rotation，成为明确的 production rotation owner；
- 持有 materialization snapshot、retry 状态和拆除状态；
- 维护当前 watch audience 连接计数；
- 确保每 section 只有一份物理 watch；
- 将现有 watch 告警扇出给所有当前页面；
- 首个相关页面连接时从数据库装配；
- PUT 成功后立即 reconcile；
- 最后页面断开时拆除全部物理 watch，但不改 desired；
- 暂态装配失败按有界退避重试，并用 revision/epoch 使旧重试失效；
- 永久装配失败停止无意义重试但保留 desired 和失败原因；
- policy 改动遵守 materialization epoch 的现有不变量；
- STOP/更新与在途 arm/disarm 不得产生旧操作复活。

不要重新实现旧 authority actor、投影帧、effect batch、双 ACK、audience ledger 或 leader 选举。
L2 的页面 presence/60 秒退出不属于本任务；不要借 coordinator 提前宣布 L2 完成。

本地旧的直接 `START_WATCH`/`STOP_WATCH`/`UPDATE_POLICY` 不得形成绕过 desired HTTP 的第二真相。
本地前端必须停止走该写入路径；服务端应 fail-closed 拒绝或以单一 coordinator 语义处理旧本地 mutation，
但不得影响公网仍使用的 connection-scoped 命令合同。
