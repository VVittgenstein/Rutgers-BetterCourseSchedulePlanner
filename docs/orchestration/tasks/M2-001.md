### A4. 共享 WatchClient 自动重连状态机

在共享 `WatchClient` 建立单一、可测试的 attempt state machine：

- 只对意外 `close` / `error` / session preparation 或连接失败自动恢复；
- 退避基线严格为 `1s → 2s → 4s → 8s → 16s → 30s → 30s…`，无 jitter、无限重试；
- 公网 `Retry-After` 可以把某一次等待延长为 `max(exponential, Retry-After)`，但不能缩短退避；
- 同时最多一个 session preparation、一个 timer、一个 socket attempt；同一 socket 的 error+close 只
  产生一次 retry；
- 每次 attempt 有 epoch/token；旧 socket 的 OPEN/message/error/close、旧 validate promise 与旧 timer
  无论多晚到达都不得改变当前 state 或创建新连接；
- OPEN 取消 timer，并把**下一次**意外断线的退避重置到 1 秒；
- `connect()` / 明确 Resume 清除 `userStopped` 并立即 attempt，不等待旧 backoff；
- `disconnect()` 设置 `userStopped`、关闭 socket、取消 timer/in-flight ownership；之后推进所有 fake
  timer、resolve/reject 所有旧 promise 都不得复活；
- `dispose()` 是永久 explicit stop；unmount 后无 timer、socket 或 state callback；
- 暴露明确的 `RECONNECTING`（或等价、可订阅的 retrying state）供 UI 区分意外恢复与显式停止，
  但不得把 OPEN 冒充完整 Readiness。

timer/scheduler 必须可注入，测试使用 fake clock，不得 sleep。

### A5. public-only mutable NonceHolder 与 validate-before-connect

新增 public-only 的内存态 session holder，通过目标中立的 shared hook 注入 runtime/WatchClient：

- 从 embedded bootstrap 的 canonical nonce 初始化；不写 localStorage/sessionStorage/cookie，不回写 DOM；
- `current()` 是 ProductClient HTTP session header 与 WatchClient WS query 的共同来源；
- public 的**每一个** socket attempt（包括首次）先 single-flight `prepare()`：
  - `POST /api/v1/session/validate`；
  - `credentials: same-origin`、严格 JSON、body 只含 `{nonce}`（locale 可省略，让服务器按
    Accept-Language 回退）；
  - 不得使用会自动包业务 envelope 的通用 mutation helper；
  - 严格解码外层 `{protocolVersion,data}` 与内层 exact one-of `{valid:true}` / `{renewed:nonce}`；
  - `valid:true` 保持当前 nonce；`renewed` 必须先原子替换 holder，再允许 socket factory 读取；
  - 并发 prepare 共享同一个 promise；完成后释放 single-flight，下一 attempt 必须重新 validate；
  - fetch failure、非 2xx、malformed/dual/null/noncanonical body 均不得更新 holder、不得创建 socket；
  - 429 读取合法 `Retry-After` 并反馈给共享重连 delay；非法值按普通退避处理。
- 服务器重启（registry 清空）时：旧 nonce → renewed → socket URL 只含新 nonce；之后 ProductClient 的
  authenticated HTTP header 也只读新 nonce；
- local target 不注入 prepare hook，不请求公网 validate path，继续使用 local bootstrap session。

shared 文件不得出现 public-only route/类型；public 文件不得引入 local capability。必要的端口使用
目标中立词义。

### A6. 公网页面内 reconnect plan：不是 selection，也不是 active id

仅给没有 durable `WatchIntentPort` 的公网路径维护一份页面生命周期内的 section+policy plan。它是
重连数据源，不持久化、不跨刷新、不包含 `activeWatchId` 或 episode 消耗：

- START 手势真正发出前同步写入 section+policy；START_RESULT ACTIVE 保留；明确 REJECTED 删除该项；
- START response 丢失后意外断线仍保留，因为用户手势可能已经生效；
- STOP 在发送前同步删除，STOP 与断线竞态不得复活；
- UPDATE_POLICY 在发送前同步写最新 policy；重连只使用最新值；
- Remove 一个未运行/未接受的 section 时同步删除相应项；
- 意外断线保留 plan，但立即清旧 active ids、pending transport、episode、alert、observation 和 green；
- 新 OPEN 后从 plan 发送**恰好一个** START batch；selected-but-never-started、已 STOP、已 Remove、明确
  Rejected 的 section 不得出现；
- 显式 Disconnect 暂停且保留 plan，不自动重连；明确 Resume 后 re-arm plan；浏览器刷新/unmount
  销毁 plan，符合公网生命周期“刷新/重启归零，tab 存活自动恢复”；
- 重连后仍 OPEN 的 section 再产生一轮初始提醒是已批准产品决定；不加 resume cursor/hint，不改协议；
- 本地有 durable intent，绝不能走这张公网 plan 或发送 legacy START/STOP/UPDATE_POLICY。意外重连 OPEN
  后由现有 coordinator attach 物化，并由 OPEN 后新 issued 的成功 desired GET 解除 R4 cutoff。

不得把 selection 当 re-arm 来源；selection 只是页面列出的课，不能复活用户从未开始或已经停止的课。

### A7. 最小 UI 语义

- retry/backoff/validate 阶段显示“正在重连”或等价非绿状态；旧 active 数与 Watching badge 必须为零；
- 显式 Disconnect 后显示已停止自动恢复，并提供明确 Resume/Connect 动作；
- Resume 不重新解释 selection，只恢复 reconnect plan（公网）或重新 attach durable intent（本地）；
- M2 只表达 transport recovery，不新增 READY/DEGRADED 五环总判定；完整 Readiness 留 M3。

### A8. 必须有的判别测试

至少覆盖以下真实反例：

1. fake timer 精确断言 `1/2/4/8/16/30/30`，并证明 30 秒后继续；
2. 同一 socket error+close 只安排一次；OPEN 后下一轮从 1 秒重启；
3. backoff、validate pending、CONNECTING 三个阶段显式 Disconnect，推进/resolve 所有旧工作仍无 socket；
4. 手动 Resume 立即 attempt，不等待旧 timer；stale old socket 的所有事件不影响当前连接；
5. public 每个 attempt 的严格顺序是 validate success → read holder → socket factory；
6. 三个并发 prepare 只有一次 HTTP；下一独立 attempt 会再次 validate；
7. valid 保持票；renewed 后 WS query 与随后 ProductClient header 只用新票；
8. malformed/dual/null/noncanonical/non-2xx 不更新 holder、不建 socket；429 服从较长 Retry-After；
9. 模拟 registry restart：旧票 renew → 新 WS OPEN → re-arm 成功；
10. public ACTIVE A(policy X) → 意外 close → 新 OPEN → 正好一个 START A(X)；
11. START response 丢失后 close 仍 re-arm；STOP 已发出后 close 不 re-arm；policy edit 后用最新 policy；
12. 只 selected 未 START、已 Remove、明确 Rejected 均不 re-arm；
13. explicit Disconnect 不重连，Resume 后才 re-arm plan；刷新/unmount 后 plan 与 timers 都消失；
14. local durable-intent 路径意外重连时不发送 legacy lifecycle command；OPEN 后新 GET 前不绿，GET 后
    coordinator 四元组匹配才绿；
15. 现有 `without automatic restart` 测试翻转并拆成“意外断线恢复”和“显式断开不恢复”；首次连接失败
    不再丢用户已经发出的 START plan。

测试必须使用 fake socket、fake timer、held promise 和真实组件入口；不能只测试独立 helper，也不能用
固定 sleep 猜时序。
