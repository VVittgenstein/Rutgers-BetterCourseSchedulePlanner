### A3. P1：持续 materialization 必须真实，不能只在首次 arm 时检查

当前三个条件组合后会永久假绿：

1. `DesiredWatchCoordinator` 对 armed 且 policy 相同的 watch 直接 adopt，不重新判断当前物化条件；
2. shared maintenance 的 term/campus sweep 没有覆盖 synthetic owner；
3. coordinator tick 只看 audience/retry，不看 materialization 与 owner live set 漂移。

必须修成：

- section 先成功 arm、后来从 Catalog 消失时：物理 owner watch 被撤下，desired policy 保留，
  GET 返回 `PERMANENT/SECTION_NOT_FOUND`，绝不继续显示 materialized；
- term/campus 后来失效时同样撤下并给出正确永久原因；
- target/gate 暂态不可用时清除旧绿态、保留 desired、按 stamp 安全重试；
- manager-side watch 意外消失时，即使 audience/retry 都没变化，tick 也能发现 section/id 漂移并清除旧 stamp；
- 健康、仍合法、policy 未变的 owner watch继续原地 adopt，不重启 episode；
- 不把 Catalog/term/campus 检查搬回 CAS writer；writer 仍只保存意图。

最低反例：

1. admitted → arm → Catalog 变 `SectionNotFound` → tick/reconcile；
2. admitted → arm → term/campus 失效 → maintenance；
3. admitted → arm → 直接 manager-side stop → coordinator tick；
4. 暂态失效 → 旧 stamp retry → 新 revision/policy；
5. 健康 watch 多次 maintenance 不改变 activeWatchId/episode。

### A4. P1：rotation 必须覆盖所有预算增长并在并发下只执行一次

当前 terminal `STALE_REVISION`/`LIMIT_EXCEEDED` 会写 receipt，但 coordinator 只在 `COMMITTED`
后检查 rotation。9 个 START receipt 加 2039 个唯一的第十门 limit receipt 可填满 2048；随后
正确 STOP 也永久 `AUTHORITY_FULL`，tick/restart 都不恢复。

必须修成：

- production rotation owner 覆盖所有会增长 receipt/tombstone 的提交结果，而不是只看 `COMMITTED`；
- 启动、tick 或下一次提交能从 threshold/hard-full 状态恢复，正确 STOP 不得永久 503；
- full 时仍保持“非终局、无 receipt、同 id 可重试”的存储合同；不得伪造成功或自动重放用户手势；
- budget check 与 rotation act 必须在同一 coordinator 排他域内重查，两个并发 caller 对同一 due
  状态只能把 generation 增加一次；
- threshold-crossing 响应必须自洽：顶层 authority generation、`committed` revision/epoch 和返回
  `state` 中对应 entry 不得跨 rotation 互相矛盾；
- rotation 仍不得重启健康物理 watch。

最低反例：

1. 只靠 stale/limit receipt 到 threshold，恰好一次 rotation；
2. 从 2048 receipt 的重启数据库进入生产路径，能自动恢复，随后正确 STOP 成功；
3. 两线程同时 `rotate_if_due`，generation 只加一；
4. threshold-crossing COMMITTED/terminal response 的所有 generation/revision 字段一致；
5. replayed terminal refusal 仍保留原 409 语义。

### A5. P1：Full Reset 必须是 authority 与物理 owner 的同一生命周期屏障

当前顺序 `watch.stop → SQLite clear → on_authority_cleared` 与 attach/PUT/reconcile 并发时，
旧 authority 可在第一次 stop 后重新 arm；clear 完成后只忘 active id，留下 authority 已空但仍运行的
orphan watch。

必须修成：

- reset 与 coordinator reconcile/materialization 使用明确的同一排他/屏障协议；
- reset 成功返回前，等待所有旧 generation 的在途 reconcile 失效并完成最终物理 stop；
- reset 成功后同时满足：authority entries 空、generation 抬升、owner watch 空、active count 0、
  materialization record 空、不会再从旧 snapshot 发 alert；
- reset 后 socket 仍可用于新的正常页面/desired；runtime shutdown 的 sealed socket 则不可重建 owner；
- `ensure_owner_connection` 必须尊重 sealed 状态；`seal_and_stop` 后 transport 和 owner start 都失败；
- reset 事务失败或忙时不得把 coordinator 留在“记录忘了、watch 仍活”状态。

最低反例：用 external SQLite transaction 阻塞 clear，在第一次 stop 后并发 attach 与在途 PUT/reconcile，
再释放 transaction；reset 返回后逐项断言 authority/owner/active/alert 全空。

### A6. P1：前端所有 authority 响应进入一个有序域

当前 GET 只和 GET 排序；PUT 不使在途 GET 失效，多个 PUT 也不互相排序。旧 GET/旧 PUT 的全量
snapshot 可在新 STOP 之后覆盖 tombstone，重新显示 `WATCHING`。

必须修成：

- GET 与 PUT 的 authority snapshot 应用进入同一 monotonic operation/order domain，或严格串行；
- 较旧响应永远不能降低 generation/revision/epoch/policy 投影；
- 409/503/transport failure 按合同重读，但不自动重放原用户手势；
- `START_RESULT`、`WATCH_STOPPED` 及后台 retry/materialization 改变后，页面通过同一个有序 GET
  刷新 projection；这不是 desired 实时跨 tab 同步，不引入第二 WS；
- GET 失败立即清旧 projection，绝不保留旧绿态。

最低 deferred-promise 测试：

1. GET 在 STOP PUT 前发出、在 PUT 响应后返回；
2. 两个不同 section 的 PUT 反序返回；
3. retry 成功广播 START_RESULT 后从 PREPARING 变 WATCHING；
4. unexpected WATCH_STOPPED 后不再 WATCHING；
5. 读取失败后旧 green 不可见。

### A7. P1：任何 selection 路径都不能隐藏仍 desired/运行的 watch

晚加入页面不会收到历史 START_RESULT，所以旧 `active[]` 可为空；`SectionSelectionAction`、
`WatchWorkspace` 和 `remove()` 仍可能仅凭 `active[]` 允许删除 selection，而 desired 与物理 watch
继续存在。authority LOADING/FAILED 时同样可能发生。

必须修成：

- local durable-intent target 的 selection removal 以 authority 为准，不以旧 `active[]` 为准；
- authority 不是 READY 时，所有可能隐藏/移除 section 的动作 fail closed；
- desired policy 非空时，必须先成功 STOP desired，才能移除 selection；
- 即使历史数据出现 desired entry 不在 selection，watch desk 也必须把该 entry 显示出来并允许 STOP，
  不能形成 UI 不可管理的孤儿；
- `SectionSelectionAction`、desk、provider 的所有入口都覆盖，不只修一个按钮。

最低真实渲染测试：late-page `active=[]` + GET WATCHING、GET LOADING、GET FAILED、desired 与 selection
不一致；每种情况都不得让仍 desired 的 section 从管理 UI 消失。
